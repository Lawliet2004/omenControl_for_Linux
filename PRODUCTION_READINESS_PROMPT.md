## 1. Fix partial diagnostics through the actual clients

The client supplement currently tries to decode that null as `Vec<SensorSample>` and returns `Internal` for an eligible real-daemon report. For a legitimate failed sensor read, retain the original report and skip the NVIDIA supplement. For valid arrays, retain existing eligible supplementation, acquisition timestamps, attribution, and deduplication. Handle missing or malformed fields explicitly and check older report shapes before changing the contract.

The direct-read-only diagnostics builders in `crates/cli/src/main.rs` and `gui/src/data.rs` also propagate sensor errors with `?`. Make the reporting contract consistent where applicable. Review other optional collectors, including network, for partial failure behavior. Test real-marked reports with null/error, empty success, a populated array, legacy success, malformed data, and fixture reports. Exercise the daemon, shared client, CLI JSON, and GUI export paths with isolated inputs. Keep user-only records private and redact sensitive data from published evidence.

## 2. Harden IPC, authorization, and service availability

Start with `crates/daemon/src/server.rs`, `crates/ipc/src/{protocol,client,peer}.rs`, `crates/daemon/src/service.rs`, and `packaging/polkit/com.omenlinux.policy`. Reuse the existing versioned protocol, request correlation, peer binding, and per-UID/global admission limits.

- Audit framing in both directions. The server currently decodes request bytes with `from_utf8_lossy`. Reproduce malformed UTF-8 inside otherwise valid JSON and require rejection before authorization or dispatch. The client sets a per-read socket timeout. Reproduce a trickling reply and verify an absolute end-to-end deadline that covers partial input and skipped frames, with a separate bounded budget for interactive authorization. Exercise missing newline, truncated EOF, blank/foreign frames, bad JSON, unknown operation/version, oversized request/reply, and the exact limit boundaries. Keep version-1 compatibility for supported callers. Reconcile request and reply limits with settings imports and diagnostic exports and return actionable errors when a valid input exceeds the transport contract.
- Test peer disappearance, socket replacement or concurrent startup, stale socket ownership, PID reuse, authorization denial/cancel/expiry, lost polkit or D-Bus, and a service restart between preview and action. Check identity and operation scope at mutation time. Keep control and admin actions distinct, mock authorization confined to its private fixtures, and writes fail-closed. A stale approval or an action queued for an old service must have zero effects on a replacement service.
- Exercise idle-client displacement, same-UID/global saturation, slow and stuck providers, SIGTERM, and client disconnect before or during dispatch. Bound workers, I/O, timeouts, and response sizes. Preserve responsiveness of independent operations, especially monitoring and fan recovery. Distinguish a rejected write from a lost reply with unknown outcome. Reconcile the latter with a fresh readback or the existing transaction identity before retrying. Avoid replaying writes against a new peer.

**Pass criteria.** Real server/client tests show invalid and unauthorized requests produce zero side effects. Normal clients recover after load, loss, and restart. Supported older clients and daemons produce documented outcomes. Timeout and uncertain-outcome tests verify state and cleanup as well as error text.
