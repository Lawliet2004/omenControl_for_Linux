# Goal: Complete remaining OMEN Linux implementation — verified, implemented, or explicitly blocked

- Status: active
- Created: 2026-11-08
- Updated: 2026-11-09

## Objective

Every item in the whole repo that is not verified, not implemented, or unsure is either implemented with passing automated tests, verified with named physical/external evidence, or recorded as blocked with the exact missing interface/device/approval needed. No fixture pass is counted as physical validation.

## Success criteria

- [x] cargo test --workspace --locked passes in debug and release, with counts recorded
- [x] cargo clippy --workspace --all-targets --locked -- -D warnings and cargo fmt --check pass
- [ ] Every remaining gap from the whole-codebase audit has a tracker entry marked implemented, verified, or blocked with missing evidence/approval named
- [ ] No live fan/RGB/charge/MUX/profile write, host install, or suspend/reboot occurs without a separate exact-target approval
- [ ] Updated docs/IMPLEMENTATION_STATUS.md, docs/CONTINUATION_CHECKLIST.md and docs/evidence/validation-summary.json attribute each result to its exact binary/package, no evidence reattributed to new code

## Non-goals

- Inventing WMI commands, EC addresses, device protocols, or compatibility for unknown hardware
- Overwriting revision 10-26 evidence as though it tested new code or claiming Windows parity from HP SDK analysis alone
- English-only interface scope creep: translations remain out of scope per user instruction
- Concurrent multi-GPU reporting until stable PCI identities, source deduplication and selection behavior are specified and verified with two distinct devices in fixtures
- Automatic launcher editing and Snap wrapping; launcher command stays user-configured; Zoom, sandboxed Legendary, AppImage discovery without a verified route, and parser gaps stay out until pinned upstream examples and fixtures exist
- Live file watching: direct TOML edits and imports from a separate CLI process do not need live reload for this slice; unrelated preferences keep existing apply/restart behavior

## Constraints

- Reference device is HP Victus 8C30 / BIOS F.10 / kernel 7.0.0-38-generic with no manual pwm1/pwm2; unknown devices stay read-only
- Default daemon stays read-only; experimental writes require exact-target opt-in, pinned actuator, thermal preflight and independent recovery
- GUI and game processes stay unprivileged; daemon sandbox is not widened for hardware access
- History resize preserves gaps, original acquisition timestamps and source labels in place; clear history only on source identity change; open history text snapshot stays stable until explicitly refreshed as during normal polling; chart views, refreshed history text and new CSV exports reflect the new buffer
- Polling/freshness: keep current freshness bounds, stale-control gating and NVIDIA query limits; never read config from chart rendering, sensor lookups or on every poll; keep worker off GTK main thread and avoid duplicate workers; apply validated values from successful save to existing poller and GUI freshness consumers
- User and Service settings stay isolated; keep current values after cancellation, invalid input or failed write; state accurately in import feedback which changes take effect now
